# 상위 .git 삭제로 내부 리포지터리 복구

## 코드
- 디렉터리 구조 (문제 상황 예시):

```
2026-7-14/
├── .git/              ← 바깥 저장소
└── project/
    ├── .git/          ← 안쪽 저장소
    └── index.
```

- 오류 재현 명령 및 출력 예시:

```
$ git branch Antigravity
fatal: not a valid object name: 'main'
```

## 오류 코드
- `fatal: not a valid object name: 'main'` — Git이 현재 HEAD/브랜치 참조(`main`)를 찾지 못해 발생합니다.
- 원인(요약): 상위 폴더에 `.git`가 존재하여 상위 리포지터리가 우선 참조되고, 내부 프로젝트의 Git 메타데이터(HEAD, refs 등)가 혼동되어 브랜치 이름이나 HEAD가 올바르게 해석되지 않음.

## 해결 방법
1. 문제 위치 확인 및 안전 점검

   - 명령 예시:

   ```bash
   # 워크스페이스에서 .git 디렉터리 위치 확인
   find . -type d -name .git -maxdepth 3
   ```

2. 상위(바깥) `.git` 제거 후 내부 리포지터리로 복구

   - 주의: 상위 `.git` 제거 전에는 원격/백업이 있는지 확인하세요. 잘못 제거하면 상위 리포지터리의 기록이 손실됩니다.

   - 명령 예시 (상위 저장소 경로에서 실행):

   ```bash
   # 상위 .git 제거 (경로를 반드시 확인 후 실행)
   rm -rf /path/to/outer/.git

   # 내부 프로젝트로 이동하여 새로 초기화
   cd project
   git init
   git add .
   git commit -m "Initialize inner repo after removing outer .git"
   git branch -M main
   git checkout -b Antigravity
   ```

3. 필요 시 원격을 재설정하고 푸시

   - 예시:

   ```bash
   git remote add origin <원격_URL>
   git push -u origin main
   git push -u origin Antigravity
   ```

## 해결 완료
- 노트 작성 및 커밋 준비 완료. 상위 `.git` 제거 후 내부 리포지터리 초기화로 문제 해결 가능.

## 정리
- 원인: 중첩된 `.git`로 인해 Git이 잘못된 리포지터리를 참조함.
- 핵심 해결: 상위 `.git`을 안전하게 제거하고, 내부 프로젝트의 `.git`을 초기화(또는 복원)하여 브랜치와 HEAD를 정상화.
